# Сценарий демонстрации (4 минуты)

Цель: за 4 минуты показать весь путь — от загрузки видео до ответа на вопрос по лекции,
и объяснить, почему это не «ещё один поиск по словам».

## За 10 минут до защиты

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run.ps1
```

Дождитесь прогрева (в консоли `models are warm`, первые 3–4 минуты). Проверьте
`http://127.0.0.1:8000/api/health` — все пункты `ok`.

Откройте библиотеку: одна готовая лекция уже должна быть. Если нет — загрузите
`videos_examples\пример_1.mp4` заранее (обработка 7,5-минутной лекции занимает ~4–6 минут).

## 0:00–0:40 — Проблема

> «Лекции — это часы видео. Найти в них ответ можно только перемоткой, а поиск по названию
> не работает. Lectora индексирует смысл: вы спрашиваете словами — получаете момент в видео.»

Покажите библиотеку, карточки, статистику: сколько часов и смысловых фрагментов в индексе.

## 0:40–1:30 — Поиск по курсу

1. `Ctrl+K` — командная палитра.
2. Введите: **«формула объёма конуса»** (по смыслу, не по названию).
3. Enter — страница результатов: таймкоды, подсветка, релевантность, время ответа.
4. Клик по результату — плеер перематывается ровно на нужный момент, субтитры включаются.

Акцент: «Поиск идёт по смыслу: слова "объём" и "конус" в запросе могут стоять в другом
порядке, а в лекции звучать как "одна треть площади основания на высоту"».

## 1:30–2:20 — Внутри лекции

1. Вкладка **«Поиск»** справа: введите **«площадь поверхности сферы»**.
2. Покажите линию-«карту лекции» под плеером: разделы и оранжевые метки найденных фрагментов.
3. Клик по результату — переход на таймкод; транскрипт подсвечивает совпадения и следит
   за воспроизведением.
4. Клик по любому предложению в транскрипте — перемотка на него.

## 2:20–3:10 — Конспект и структура

1. Вкладка **«Конспект»**: обзор лекции, ключевые термины, 7 разделов с таймкодами.
2. Клик по разделу — переход к началу.
3. Подчеркнуть: конспект собран локальной Qwen2.5-7B, без облака; если модель выключить —
   останется экстрактивный конспект, продукт продолжит работать.

## 3:10–3:50 — Вопросы по лекции

1. Вкладка **«Вопросы»**: **«Что такое прямоугольный параллелепипед?»**
2. Ответ + чипы-цитаты с таймкодами. Клик по цитате — переход к первоисточнику.
3. Показать, что ответ не выдуман: это фрагменты лекции.

## 3:50–4:00 — Технологии и надёжность

* Vosk (офлайн ASR) → bge-m3 (эмбеддинги) → PostgreSQL FTS → bge-reranker → Qwen2.5 (конспект/Q&A).
* Очередь задач переживает перезапуск, прогресс по SSE, ошибки показываются человеческим языком.
* Всё локально: нет API-ключей и передачи данных наружу.

## Запасные ответы на вопросы жюри

**«Почему Vosk, а не Whisper?»**
Требование кейса и полностью офлайн-запуск на CPU. Whisper точнее в пунктуации, но требует
больше ресурсов; архитектура позволяет добавить второй движок за один интерфейс.

**«Насколько быстро?»**
7,5 минут видео: ~2 минуты распознавания, ~30 секунд конспекта, поиск 2–3 секунды
(повторный — ~20 мс за счёт кэша реранка).

**«Что если модель недоступна?»**
Конспект и структура строятся экстрактивно, Q&A отдаёт релевантные фрагменты; интерфейс
честно помечает, что LLM не использовалась.

**«Масштабирование?»**
Очередь уже в БД (`SKIP LOCKED`), воркеры выносятся отдельным процессом; эмбеддинги
переезжают в pgvector, кэш — в Redis. Фронтенд и API не меняются.

**«Безопасность?»**
Белый список расширений, UUID-имена файлов, защита от path traversal, лимит размера,
`nosniff`, отсутствие исполняемого контента. Аутентификация — за reverse-proxy.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `health` показывает `llm.available=false` | `scripts\start_llm.ps1`, подождать 20 с |
| Поиск/загрузка отвечают 503 | проверить `data\logs\server.err.log` |
| Видео не проигрывается | открыть `/api/lectures/{id}/media` — должен отдаваться Range |
| Долгая обработка | это ASR на CPU; для демо используйте профиль «быстрое» |
